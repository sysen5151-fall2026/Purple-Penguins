# Route Table

The Flask homepage collects recipe preferences and displays backend-calculated ingredient ownership and additional-purchase estimates. Recipe generation defaults to deterministic local recipes and can be configured for OpenAI; grocery pricing defaults to saved local HTML fixtures, with optional live Kroger API pricing and an explicit in-memory stub. Fixture prices are illustrative and are not live retailer prices.

| Method | Path | Purpose | Planned behavior | Related F.2 functions | Status |
|---|---|---|---|---|---|
| GET | `/` | Load the Recipe Roulette browser interface | Render already-owned ingredients, budget, and optional dietary-restriction controls; explain the simulated login prerequisite; disclose recipe-generation and grocery-pricing modes separately. | F.2.2, F.2.3, F.2.7 | Implemented — browser UI |
| POST | `/api/v1/recipes` | Submit preferences and generate recipe results | Validate the unchanged JSON request, prepare a normalized/deduplicated ownership context, generate recipe names and quantity-bearing ingredient requirements through the configured recipe stub or OpenAI adapter, obtain package data from Kroger, local HTML fixtures, or explicit dictionary demo pricing, normalize compatible package units to recipe quantities, and return the unchanged success schema. Pricing failures use safe `502`/`503` backend-failure responses; validation remains `400`. | F.2.4; verified subfunctions F.2.4.1–F.2.4.4; transient recipe-generation retries are F.2.5; cost calculation has no separate modeled function | Implemented — HTML fixture default; opt-in Kroger API; explicit stub mode |
| POST | `/api/v2/recipes` | Return ingredient-use and package-purchase estimates | Accept the same request schema as v1; preserve all v1 result fields and add whole-package purchase totals, package-budget status, and per-ingredient selected-product/package provenance. Package estimates are per recipe; missing package information is explicitly unavailable. | Versioned extension of F.2.4; no new model IDs assigned | Implemented — consumed-quantity and package-purchase costs distinguished |

The “Spin for Recipes” action posts the unchanged request body to `/api/v2/recipes`; `/api/v1/recipes` remains available with its original schema and cost semantics. F.2.4.3 specifies a normalized, deduplicated internal ownership list before F.2.4.4 submits the recipe request. The OpenAI adapter returns validated recipe names and quantity/unit-bearing ingredient requirements; it does not return prices. Grocery product pricing remains a separate operation. Backend response assembly identifies ownership and calculates cost fields. XML10 has no separate modeled cost-calculation function, so `calculate_recipe_costs` remains an unallocated service-level helper. The browser displays ingredient-use and package-purchase estimates separately and does not filter recipes.

The team selected the official Kroger Products API as its final live pricing source. This is a source-interface substitution for S.1 Webscraping: the API returns JSON rather than retailer HTML. The local HTML fixture mode remains the default coursework mode and is not live pricing. `html_live` remains disabled. See `docs/traceability.md` for the verified S.1 action mappings and required Innoslate revisions.

OpenAI mode requires server-side `OPENAI_API_KEY` configuration. The request contract and successful response fields are unchanged. Transient connection, timeout, rate-limit, and server failures are retried up to ten total attempts; missing credentials, authorization failures, malformed structured output, and other non-transient errors are not retried. No API key is returned to the browser.

The initial route set intentionally excludes login, customer support, saved recipes, recipe-detail, and shopping-list endpoints. Those routes should be considered only when F.2.1, F.2.5, F.2.6, or F.2.8 is scheduled and its behavior is confirmed.

F.2.2 has a modeled **Login Approved** input from F.2.1. The page identifies this prerequisite as simulated demo mode; no authentication is performed.
